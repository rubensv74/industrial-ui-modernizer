# Shape

Use before implementation when the structure, interaction model, or responsive composition is not already settled.

## Procedure

1. Establish the user's job on the surface and the decision/action that defines success.
2. Inventory required information, actions, filters, states, permissions, and dependencies from evidence.
3. Separate **must remain visible**, **contextual**, and **progressively disclosed** information.
4. Define page regions and component responsibilities before styling.
5. Define loading, empty, error, stale, disabled, validation, and unsaved-change states.
6. Define the responsive transformation for desktop, tablet, and narrow layouts that the product actually supports.
7. Identify data-volume risks: pagination, virtualization, sticky headers/identity columns, horizontal grid scroll, and filter scalability.
8. Produce an implementation-ready component map and list unresolved assumptions.

Do not write a prettier version of an unclear workflow. Resolve the workflow first.

## Output

- surface purpose;
- evidence/constraints;
- component hierarchy;
- interaction/state model;
- responsive model;
- data-volume strategy;
- risks and open questions;
- acceptance checks.
