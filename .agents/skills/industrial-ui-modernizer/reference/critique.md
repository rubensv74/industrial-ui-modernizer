# Critique

Critique evaluates whether the interface communicates and operates clearly; it is not a source-code audit.

Review:

- hierarchy and first-read clarity;
- information density versus cognitive load;
- alignment and rhythm;
- action prominence;
- selection/filter context;
- grouping and card usage;
- typography hierarchy;
- status legibility;
- consistency across repeated patterns;
- whether visual styling fits an operational product rather than a generic marketing/SaaS template.

Preserve product truth. Do not propose removing information merely because the screen is dense. First determine whether the density is necessary, then improve grouping, prioritization, and progressive disclosure.

Separate:
1. observed evidence;
2. likely usability consequence;
3. recommended design change;
4. items requiring user/runtime confirmation.
